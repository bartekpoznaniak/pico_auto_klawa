## Najważniejsze problemy, które rozwiązaliśmy

- Początkowo `MOVE` nie docierało do Pico, bo `receive_time()` czytało wszystkie dane z portu i odrzucało linie niebędące `TIME,...`. Rozwiązaniem było przekazywanie takich linii do obsługi komend.

- Ustalenie właściwego portu COM było kluczowe: jeden port to konsola REPL, drugi to `usb_cdc.data`; port używany przez działający skrypt synchronizacji czasu jest właściwym portem danych.

- Blokujące `print()` przy rozłączonym/niekonsumowanym REPL-u potrafiło zatrzymywać pętlę po naciśnięciu przycisku; usunięcie zbędnych printów przy ruchu rozwiązało zawieszanie zegara.

- Minimalny test `test_hid.py` potwierdził, że sam raport HID absolutny działa — kursor przesunął się po `send_report()`.

## Ważne ustalenia

- Ekran ma rozdzielczość **3840 × 2160**.

- Współrzędne `MOVE,x,y` są w pikselach ekranu.

- Wartości HID są skalowane do zakresu 0–32767.

- Report ID myszy to **7**.

- `Cel:` na OLED pokazuje ostatni cel zadany Pico, a nie rzeczywistą pozycję kursora Windows.

- Nie łączymy jeszcze automatyzacji z OLX ani nie wykonujemy płatności automatycznie.

- prompt:

Kontynuuj projekt "Pico HID Automation".

Mam działający Raspberry Pi Pico 2 z CircuitPython jako fizyczną mysz HID dla Windows.

Aktualny stan:

- boot.py konfiguruje klawiaturę HID, własną mysz absolutną (Report ID 7), konsolę USB CDC i kanał danych USB CDC.
- code.py obsługuje OLED SSD1306 (SDA=GP4, SCL=GP5), RTC, przyciski GP14/GP15, mysz absolutną i komendy z Windows.
- Windows wysyła komendy przez pyserial: MOVE,x,y, CLICK, QUIT.
- MOVE,x,y działa: Pico przesuwa kursor absolutnie na ekranie 3840x2160.
- CLICK jest przygotowany, ale wymaga jeszcze bezpiecznego testu.
- OLED pokazuje zegar, status synchronizacji, ostatni cel i status operacji.
- ustaw_czas_pico.ps1 synchronizuje czas Pico przez USB CDC; Pico odpowiada OK lub ERROR.
- GP14 przesuwa kursor do (10,10), GP15 do (1920,1080).
- Projekt jest w Git.

Ważne zasady:

- Nie używaj pyautogui do ruchu myszy ani klikania; ruch i klik mają wykonywać fizycznie Pico przez USB HID.
- Nie ruszaj jeszcze automatyzacji OLX ani płatności.
- Zachowaj istniejącą architekturę: Windows wysyła komendy, Pico wykonuje HID.
- Zachowaj ekran 3840x2160 i skalowanie HID 0-32767.
- Zachowaj Report ID 7.
- Pamiętaj, że print() w code.py może blokować program, gdy REPL nie jest konsumowany; ograniczaj printy w pętli głównej.
- Nie zmieniaj boot.py bez potrzeby; przy każdej zmianie boot.py wymagany jest fizyczny restart USB Pico.

Następny krok:
Zbuduj prosty, bezpieczny "rejestrator kroków" w Pythonie na Windows:

1. Użytkownik klika Ctrl+Alt+R, aby rozpocząć nagrywanie sekwencji.
2. Program zapisuje MOVE,x,y przed każdym kliknięciem.
3. Program zapisuje CLICK po kliknięciu.
4. Sekwencja jest zapisywana do pliku JSON.
5. Dodaj komendę PLAY do odtworzenia zapisanej sekwencji przez Pico.
6. Dodaj bezpieczny limit kroków, opóźnienia między krokami i możliwość przerwania Esc.
7. Najpierw przetestuj na Notatniku lub pulpicie, nie na przeglądarce ani OLX.

Zacznij od zaproponowania minimalnej wersji rejestrowania i odtwarzania kroków, bez zbędnych funkcji.
